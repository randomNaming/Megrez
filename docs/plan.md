# 天权 · 实施计划（P0 基线）

> 本文是给下一位接手 agent 的施工图。用户已拍板的决策在此固化，不要再重新讨论；
> 需要改动的，先指出冲突点并说明理由，等用户确认。

## 一、核心模型（已拍板，勿改）

**生态内不再有密码。** 身份 = 一台设备上的一把密钥。

| 环节 | 谁做 | 内容 |
|---|---|---|
| 设备密钥 | 设备 | 私钥存于系统安全区（iOS 安全芯片 / Android Keystore / Windows TPM）；PIN、指纹、人脸只是**本地解锁**，从不上传 |
| 注册 | 客户端 | 生成密钥对，上报公钥 + 设备名 + 平台 + 一次性配对码 |
| 审批 | 管理员 | 后台看到设备信息，批准或拒绝；**默认拒绝** |
| 登录 | 设备 | 服务器下发一次性挑战，设备签名，服务器验签 |
| 凭证 | 天权签发 | 短期访问凭证 + 长期刷新凭证，绑定设备，可单独吊销 |

关键原则：

1. **私钥永不离开设备**，服务器只存公钥。
2. **新设备默认不可用**，必须人工批准。
3. **一次挑战只能用一次**，带有效期，防重放。
4. **一设备一凭证**，丢设备只吊销那一台。
5. 管理后台自身用「账号 + 强密码 + 动态码」登录，是新设备接入的唯一兜底路径。

## 二、必须做的安全项（漏一条就等于白做）

| # | 项 | 具体 |
|---|---|---|
| 1 | 配对码 | 注册必须携带一次性配对码；无码请求直接丢弃，不落库 |
| 2 | 审批可见性 | 审批页展示：设备名、平台、首次注册时间、来源 IP、公钥指纹，避免盲批 |
| 3 | 挑战签名 | 挑战一次性 + 有效期（建议 60 秒），签名覆盖挑战原文与设备 ID |
| 4 | 令牌 | 短期（分钟级）+ 长期（可续期）；长期凭证只存哈希；吊销立即生效 |
| 5 | 限流 | 注册、登录、后台登录分别限流；后台连续失败锁定 |
| 6 | 审计 | 记录注册/批准/拒绝/登录/吊销，含时间、设备、IP |
| 7 | 传输 | 全站 HTTPS；数据库文件权限收紧 |
| 8 | 备份 | SQLite 文件定期快照；备份不含明文私钥（本来就没有） |

## 三、数据模型（初稿）

```
devices
  id            主键
  name          设备名（用户可改）
  platform      ios / android / windows / macos / linux
  public_key    公钥
  fingerprint   公钥指纹（用于审批页辨识）
  status        pending / approved / rejected / revoked
  created_at
  approved_at
  last_seen_at
  last_ip
  note          审批备注

pair_codes
  code_hash     配对码哈希（不存明文）
  expires_at
  used_at
  created_at

tokens
  id
  device_id
  refresh_hash  长期凭证哈希
  expires_at
  revoked_at

audit
  at
  event         register / approve / reject / revoke / login / refresh
  device_id
  ip
  detail
```

## 四、接口草案（P0）

**设备侧（无需登录状态）**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/device/register` | 带配对码注册，落库为 pending |
| POST | `/api/device/challenge` | 取一次性挑战 |
| POST | `/api/device/verify` | 提交签名，通过则发令牌 |
| POST | `/api/token/refresh` | 续期 |
| POST | `/api/token/revoke` | 主动注销本设备 |

**管理侧（账号 + 密码 + 动态码）**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/login` | 登录后台 |
| GET | `/api/admin/devices` | 设备列表（含待审批） |
| POST | `/api/admin/devices/:id/approve` | 批准 |
| POST | `/api/admin/devices/:id/reject` | 拒绝 |
| POST | `/api/admin/devices/:id/revoke` | 吊销 |
| POST | `/api/admin/pair-codes` | 生成一次性配对码 |
| GET | `/api/admin/audit` | 审计查询 |

**业务侧**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/.well-known/keys` | 公钥，供各业务项目本地验签 |

## 五、业务项目如何接入（P1 的第一件事）

原则：**业务后端不每次回调天权**，只做本地验签，避免天权成为单点故障。

1. 各项目从 `/api/.well-known/keys` 取公钥（可缓存）。
2. 请求带访问凭证 → 本地验签 → 取出设备 ID 与过期时间。
3. 过期 → 客户端拿长期凭证续期；续期失败 → 拒绝，不做降级。

第一个接入样本：**crm-mini**（先做后端验签中间件，不改前端交互）。

## 六、分期

| 阶段 | 范围 | 验收标准 |
|---|---|---|
| **P0** | 骨架 + 注册/审批/挑战签名 + 管理后台 | 新设备注册后无法登录；后台批准后可登录；吊销后立即失效 |
| **P1** | 令牌 + 业务验签 + crm-mini 接入 | 无凭证访问 crm-mini 接口被拒；持有效凭证可正常读写 |
| **P2** | 审计、多设备、异常告警 | 能在后台看到每台设备的完整轨迹；丢设备能在 1 分钟内断掉 |
| **P3** | 网页端接入（通行密钥） | 浏览器端也不需要密码，且与设备身份是同一个「我」 |
| **P4** | 手机 App 接入约定 | App 内完成登录，不跳外部浏览器；首次配对一次，之后免登录 |

## 七、资源预算

| 项 | 预算 |
|---|---|
| 常驻内存 | ≤ 100MB（目标 30–60MB） |
| CPU | 验签为微秒级，可忽略 |
| 磁盘 | 主程序 + SQLite，MB 级 |
| 外部依赖 | 0 个数据库、0 个缓存服务 |

## 八、不要做的事（接手 agent 注意）

- 不要引入 PostgreSQL / Redis / 消息队列
- 不要做多用户、角色、邀请注册、邮箱找回
- 不要把密码或私钥写进代码、日志、文档
- 不要在未获批准时"降级放行"（宁可拒绝，不可静默通过）
- 不要为了兼容网页端而削弱 App 侧的设备绑定
